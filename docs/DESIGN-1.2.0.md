# 1.2.0｜服饰资产展示流程重整

## 问题与依据

用户此前只要求全队统一灰色训练 T 恤，Agent 却给了正面平铺提示词。1.1.0 的 `image-prompts.md` 把服饰和道具合在一个短段落，并将不可见人台、实穿、平铺列为并列选项；入口没有服饰资产专用路由，审阅没有对应展示标准。因此“单件、无人、纯净背景”无法稳定决定衣服的空间形态。

用户本次明确要求统一采用两张所附图片的展示方式。已实际查看两图：都是白底正面、上衣与裤装按穿着关系组合，衣服被撑起且保留褶皱和开口空间，没有可见人体或人台。本次转成默认的是这一展示约定，不是参考球衣的球队、号码、品牌、配色、护肩、护具和下装。原图仅用于本地理解和指定测试，不进入仓库、安装包或通用提示词。

## 实现

- 独立 `clothing-assets.md` 按资产范围 → 团队统一 → 参考职责 → 立体展示 → 成稿/编辑 → 审阅组织。它是服饰展示规则的唯一完整定义，入口、图像模块与审阅模块只做路由。
- 单件与整套只控制交付范围。单件仍有穿着体积；整套按同一穿着体自然组合，不拆成商品平铺清单。纯 T 恤不擅加裤子或比赛护具。
- 提示词必须正面描述支撑、空腔、松量、重力与褶皱，不能仅靠“禁止平铺”控制形体。不同服装依面料和剪裁决定体积，白底光线也须保留边界与材料。
- 款式参考与展示参考分工。既防止参考样式泄漏，也允许准确保留用户确认的已有标识、号码和层次。
- 既有图转展示格式时，明确造型重建需要改变褶皱/投影/受光，不做不可能的像素保持承诺。审阅以实际图为证据，文本完成不等于生成通过。
- 明确要求的平铺、真人试穿、背面及既有媒介仍优先；人物入景和道具不受服饰资产默认影响。

不增加图片生成器、全局设置、项目专名默认或强制模板。不改精确文本替换与安装工具。

## 验证设计

先运行原有自包含与工具边界测试，再从发布 ZIP 安装进独立项目，在只发现 film-visual 的新会话中运行 C01–C09。C01 复用导致问题的简短请求，不提示新规则；其余覆盖整套、其他面料/媒介、明确覆盖默认、道具隔离、两类图片参考及几何锁定冲突。

判据在 `film-visual/tests/cases.md` 中预先列明。按实际输出、模块读取和看图记录判断含义，不把命中词语当成通过，不把一轮文本样本称为生成稳定性证明。真实运行结果与限制见 [验收报告](VALIDATION.md)。
