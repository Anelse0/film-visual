# Midjourney：描述、词量与入口

适用于 MJ 提示词编写与压缩；不把这里的英文词量预算套到 GPT Image 编辑、视频 LOOK 或完整视觉方案。用户未指定语言时交付英文正文。具体视觉设计沿用 [design-methods](design-methods.md)，服饰内容由 [clothing-assets](clothing-assets.md) 决定，本模块负责把设计编译成适合入口的表达。

## 先辨入口

| 当前任务 | 正文写法 | 参考与边界 |
| --- | --- | --- |
| 普通 Imagine；图片作为 Image Prompt | 直接描述最终应出现的画面：主体及关系、环境、光色和媒介 | 不把 “preserve the reference / move the camera / make sure” 当生成正文；将要求改写成可见状态。Image Prompt 会影响内容、构图与颜色，不保证精确复制 |
| Style Reference | 描述新画面的主体与内容，补少量与参考相容的风格特征 | 它传递色彩、媒介、纹理、光感，不负责复制人物、物件或场地布局 |
| 明确使用 V8.1/V8.2 Edit Model、Quick Edit 或 Attach to prompt | 可以直接写改哪张图、改变什么、保留什么；不强行改成纯名词列表 | 编辑与参考保持仍需实际结果验证。不要将旧版 `--oref` / `--cref` 与 V8 编辑路线混用 |

只有“参考图 + MJ prompt”而未指定编辑入口时，按普通 Image Prompt 编写；需要交代参考职责时在正文外用一句说明。明确要求精确编辑则选择相应编辑写法，不因附件存在就擅自切换入口。看过实际图片才描述其中内容；局部新建区域标为设计提案，不声称原图已显示。

网站入口使用其实际参考栏；Discord 的 Image Prompt 需要真实图片 URL 放在正文之前，Edit Model 的 URL 则跟在 `--edit` 后。用户未提供可用 URL 时，不把本地路径、虚构链接或 `[image URL]` 占位符塞进最终 prompt，也不自动上传。`--sref` 只使用用户真实提供的图片 URL 或有效参考代码。

## 词量预算：本 Skill 的编辑约定

官方基础指南倾向简洁，但新版 Describe 会为 V8.1/V8.2 提供更详细的描述。因此目标是减少冗余、保留明确控制，不是所有任务越短越好。本轮核对的官方文档没有给出统一且可复核的数字 token 上限；不能宣称“超过 75/77 tokens 就忽略”“最多 60 个单词”或给词数乘系数冒充 MJ token 计量。V8.1 发布说明提及超长提示的自动缩短功能，但没有在该说明中给出阈值；不依赖它替用户决定删什么。

以下仅计**英文描述正文**，不计图片 URL 和参数；引号内要生成的文字仍计入正文：

| 内容复杂度 | 默认软预算 | 使用判断 |
| --- | --- | --- |
| 简单 | 20–50 词 | 单主体，少量外观或风格约束 |
| 一般 | 50–90 词 | 场所、材质、服饰展示等需要数项具体描述 |
| 复杂 | 90–140 词 | 多组人物、空间相邻/遮挡/通行/视线等多项必须关系 |

先选适合内容的档位，写完按以下取舍压缩。低于区间不补废话；超过上界先复查冗余，确有必要可以保留，不能静默删硬要求。这个范围是可调整的工作起点，不是官方推荐数字或生成效果保证。用户明确字数、语言或详略时优先遵守；英文词数不能直接套中文字符。严格字数限制与不可删内容冲突时，指出具体冲突，不假装两者都满足，也不自行拆成多张图。

需要准确报告字数、靠近预算上界或用户给硬上限时，用 [check_mj_prompt.py](../scripts/check_mj_prompt.py) 复核；平时可直接给成稿，不为计数强建文件。该工具支持 `--text`，或对已有文件运行：

```sh
python3 scripts/check_mj_prompt.py --input prompt.txt --budget complex
```

只有用户给了硬上限才加 `--max-words N`。计量将连字符复合词/英文缩写计作一个词，数字也计数；双引号内的 `--` 不误认作参数。非英文文字不套本预算，脚本会报告不适用。它只计量，不验证 MJ 解析、语义完整性或美感，不改写/截断输入，不调用服务。

## 描述取舍与压缩

内部先分出三类信息，不默认展示清单：

- **必留事实与关系**：主体身份或数量、指定服饰、物件相邻、人物前后、视线、通道、时段、媒介、指定文字。它们决定画面是否还是用户要的场景，不因词量紧张删掉。
- **必要设计选择**：一个能容纳关系的视角、关键明暗/材质差别、少量场所辨识特征。先选定再写入，不叠互斥机位、焦段、光感。
- **可删冗余**：同一关系反复叙述、同义形容词、礼貌命令、为什么这样设计的解释、故事日序或未要求显示的日期、无作用的背景清单、万能“masterpiece / 8K / ultra detailed”尾巴。用户确实要画面文字或特定效果时保留其具体要求。

用主体明确的短句表达关系；复杂空间允许完整句子，不强制退化成逗号关键词堆。先写决定画面身份与关系的内容，再补光色/媒介，减少背景抢占描述；这是组织方法，不声称官方存在固定的“首词权重衰减”公式。数量已知就精确写，只有“几名/一群”时用小组/人群表达，不自行锁定人数。

先合并重复，再删无关修饰，最后检查关系是否还完整。比如“板紧挨桌、桌旁有通道、来宾在球员后能看见两者”要保留这些联系；不要只留下“board, table, people, gate”。这类词量首先分给关系，而不是补一段校园风景或重复一遍左中右布局。参考图也不能替代文字中关键且已改变的视角/光线。

尽量写正向可见状态：不整齐排队可写 `an irregular cluster`，不是把 `queue` 放进长串否定句。真正要排除独立物件时才考虑 `--no`。官方提示其审查会逐词读取；不能用 `--no modern clothing` 或 `--no flat clothing` 这类短语排除“现代衣服/平铺衣服”，以免连服装本身也进入排除范围。服饰用正向穿着体积描述，不为压短丢掉肩部、袖筒和自然垂坠。

## 参数与交付检查

- 参数集中放正文末尾，前留空格，不夹杂自然语言；不要把句号挂在 `--ar 16:9` 后。`--no` 的逗号列表、画幅的冒号等属于各参数语法，不按“禁标点”误删。
- 未指定模型就不自动钉版本，也不加整套 Raw、Stylize、Quality、Seed。需要更少默认风格介入时可按目标采用 `--raw`，它不是“真实”或“电影感”的必填开关。画幅应有构图依据。
- 2026-09-24 核对：官方默认 V8.2；V7/V8.1/V8.2 不支持普通正文 multi-prompt `::`，当前 V8.1/V8.2 兼容表不支持 `--q`。不能从早期 V8 Alpha 帖复制旧参数到当前版；用户明确要不支持的语法时说明并给普通描述替代。风格参考自身的权重语法与正文 multi-prompt 是不同功能，不混为一谈。
- 需要画面出现文字时用双引号包住用户给定内容，不把项目名/日期自动变成招牌。不要追加与指定文字冲突的 `--no text`，也不保证长名单准确可读。
- 对照原需求复查必留关系、已选媒介、参考角色、互斥内容，再看词量和参数。短、合法都不等于语义完整。
- 默认一条完整成稿；不要附内部预算表、研究过程、多个备选或词数自评。必要的入口说明放正文外。用户只要 prompt 时直接交 prompt；不能因为生成尚未执行就在正文里加“待测”等工作状态。
